## 审查发现与落实要求

1. **不能只隐藏按钮或封住 add_trait。** `TaiSun_effect` 在授予前会收纳廷臣、写入旧旗标；`.014` 还会清王号、加合法性、改继承法及发通知。采用同一固定关闭 trigger，对交互候选/接受、死亡 action 效果、两事件的 immediate/option/after 和两个授予效果整体加保护。交互的显示和有效性也必须关闭。
2. **旧存档可能已有延迟事件。** 死亡 action 会延迟七天安排 `.002`，后者再延迟一天安排 `.014`。两事件同时加触发条件和内部效果保护；`.002` 的选人 widget 也关闭。无论引擎对已排队事件何时重查 trigger，内部册封副作用都受保护。游戏实际调度仍列入人工 R3，不把静态结论写成运行时通过。
3. **保护已有太孙与新授予分开。** 太孙特质、评分、显示、废黜、换储、登基清理均不改；太子记录和其他死亡处理不改。关闭 trigger 不接入撤销效果、通用宗室派生或既有人物 UI。皇太孙按钮已读取交互 is_shown，可不修改 GUI 文件。
4. **上游同步需要移植拓展筛选。** 当前上游典章决议的三处太子排除分别位于册封宗亲显示、皇子选项有效性和执行候选，应逐一补独立太孙排除。有效叠加集合未发现对被替换旧决议 ID 的直接 `decision:`、`execute_decision`、`has_taken_decision` 引用；同名 widget 选项值并非决议引用。
5. **本地化差异不能全部照搬。** GUI 本地化只发生空白变化；保持不动。姓名文件仅补新的选人显示键，不重新引入上游已有的重复全局姓名定义。
6. **验证不能覆盖历史交付记录。** 旧分离验证器会写 Gaming Mod 的历史 JSON，本轮不直接执行。新增目标仓库内的定向验证，比较修改前后非目标顶层定义，检查有效叠加后的授予写入位置、关闭保护及文件结构；验证结果保存本目录。
